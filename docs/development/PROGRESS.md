### Review record, round 2: commit `32743bd`

- Review 2: Codex gpt-6.1-sol, read-only. Verdict REJECT: 10 of the 11 original findings confirmed fixed, finding 3 (limits) partly fixed, plus 1 new blocker and 2 new majors. This is the second implementation attempt on the limits workstream; anything still open after this goes to the user.
- New blocker (shared resource expanded once per scope): reproduced (a 205 KB input took 5.9 s and built 30 copies of a 100,000-element array). Fix: the resource is read once per resource group and shared by its contexts; its hash, payload and byte count are computed once; context identity combines the resource hash with the scope; an explicit work budget (4,000,000 built values, shared by both input files) stops any other expansion. The same input now takes 0.24 s.
- New major (byte counter below the real size): reproduced (327 logs of 1,024 attributes passed emission and failed at serialization). Fix: every event is counted as a full persisted line (event plus a 96-byte envelope bound plus the line feed), contexts are counted with the shared resource's size, the header's other fields are counted, and the limit is injectable so tests prove the estimate is never below the real serialized size and stays within about 20 bytes per event of it.
- Spec conflict (recursion): the spec allowed bounded recursion in schema validation while ADR-027 decision 8 forbids recursion over untrusted structure. Fixed in code instead of text: tagged values are validated iteratively (200,000 nesting levels tested); the spec now says no stage recurses.
- Robustness: the folder-permission check now reads access rules through .NET (`Directory.GetAccessControl`) instead of `Get-Acl`, because Codex's environment could not load the PowerShell security module; it reports SIDs directly and still rejects a loosened folder on this machine.
- Test gaps closed: resource arrays across many scopes (200 scopes, HASH_ONLY works, FULL stops at the output budget), estimate versus real bytes for four input shapes in both modes, maximum permitted nesting (57 levels accepted and read back, 58 refused, arrays, objects and mixed), explicit work budget.
- New major (format changed without a new `schemaVersion`): accepted as a finding. User decision: bump to version 2. `RUN_EVENT_SCHEMA_VERSION` is now 2; a version 1 event is rejected with the reason `UNSUPPORTED_SCHEMA_VERSION`; spec sections 5 and 13 say version 1 was an unreleased draft. Also found while re-running the real import: the importer's identity must change whenever its output changes, so `IMPORTER.version` is now `3` (the new context hashing had changed the saved bytes under an unchanged identity, which the store correctly refused as `E_EXISTS_DIFFERENT`).
- Validation: typecheck clean; 545 unit tests pass, 2 skipped. One existing mission test (`test/evaluation-baseline.test.ts`, about 5.6 s against a 5 s default limit) timed out once under load in a full run and passed on a single rerun and on a second full run; it is not related to this work, but the new heavy tests make full runs slower, so CI timing is a risk to watch.
